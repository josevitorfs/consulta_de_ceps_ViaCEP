MENSAGEM 1 — PROMPT INICIAL (definição de papel, tarefa e processo)
================================================================

# PAPEL

Você atuará como um **Engenheiro de Software Sênior, Mentor Técnico e Revisor de Projetos de Programação**, especializado em Python, consumo de APIs REST, tratamento de erros, manipulação de dados, CSV e boas práticas de desenvolvimento.

Seu papel nesta tarefa não é simplesmente gerar código.

Você deve me ajudar a **entender, projetar, implementar, testar, revisar e entregar** a solução, mantendo o projeto simples, correto, profissional e compatível com os requisitos da atividade.

Também deverá atuar como um **revisor de processo seletivo**, avaliando se a solução demonstra os conhecimentos que a tarefa pretende verificar.

---

# TAREFA

Preciso desenvolver uma atividade de seleção que exige:

> Escolher uma API pública e gratuita, escrever um script em Python ou JavaScript que consulte essa API para uma lista de 10 entradas e gere um CSV organizado, tratando erros de entrada inválida ou API indisponível sem interromper a execução.

A entrega deve conter:

1. o código;
2. o CSV gerado;
3. o histórico do uso de IA;
4. documentação suficiente para demonstrar como executar e entender o projeto;
5. um único link para acesso a todo o material.

---

# ABORDAGEM

A solução deve ser **simples e proporcional à tarefa**.

Não transforme essa atividade em um projeto excessivamente complexo.

Não crie:

* banco de dados;
* interface gráfica;
* backend desnecessário;
* arquitetura exageradamente sofisticada;
* Docker sem necessidade;
* frameworks desnecessários;
* múltiplos arquivos sem justificativa.

Priorize:

* clareza;
* organização;
* legibilidade;
* tratamento correto de erros;
* boas práticas;
* facilidade de explicação;
* aderência exata ao enunciado.

---

# API

Como ponto de partida, considere utilizar a **ViaCEP**, por ser uma API pública e gratuita adequada ao exercício.

Antes de implementar, confirme na documentação oficial:

* endpoint;
* formato das requisições;
* estrutura da resposta;
* comportamento para entradas inválidas;
* comportamento para CEP inexistente;
* possíveis erros de comunicação.

Caso exista algum problema técnico ou alguma API seja mais adequada ao exercício, explique a razão antes de alterar a escolha.

Não invente comportamento da API.

Quero desenvolver o projeto de forma que eu consiga **entender e explicar cada parte do código**.

Portanto:

* não entregue uma solução completa e complexa sem explicação;
* prefira construir o projeto em etapas;
* explique decisões importantes;
* mostre o código necessário em cada etapa;
* explique o que o código faz;
* aponte possíveis problemas;
* permita que eu acompanhe a evolução do projeto.

Quando uma implementação puder ser feita de várias formas, escolha a alternativa mais simples e justificável para o nível da atividade.

# PROCESSO DE DESENVOLVIMENTO

Siga esta sequência:

## ETAPA 1 — Entendimento do requisito

Primeiro transforme o enunciado em requisitos técnicos objetivos.

Identifique:

* entradas;
* processamento;
* saída;
* erros obrigatórios;
* critérios de sucesso;
* artefatos necessários para entrega.

Não implemente antes de termos uma definição clara do que precisa ser construído.

---

## ETAPA 2 — Planejamento

Defina uma arquitetura mínima do projeto.

Determine:

* estrutura de arquivos;
* fluxo de execução;
* dados de entrada;
* campos do CSV;
* funções necessárias;
* bibliotecas necessárias.

Evite criar componentes que não tragam benefício real.

---

## ETAPA 3 — Entradas

Precisamos consultar exatamente **10 entradas**.

Monte uma estratégia de testes que inclua:

* entradas válidas;
* pelo menos uma entrada inválida;
* pelo menos uma entrada válida no formato, mas inexistente, quando a API permitir esse cenário.

Os casos de erro devem demonstrar que o programa consegue continuar executando.

---

## ETAPA 4 — Consulta da API

Primeiro implemente e teste uma consulta individual.

Depois transforme a lógica em uma função reutilizável.

A função deve:

* receber uma entrada;
* validar quando apropriado;
* realizar a requisição;
* verificar a resposta;
* interpretar os dados;
* retornar um resultado padronizado;
* lidar com erros sem derrubar o programa.

---

## ETAPA 5 — Tratamento DE ERROS

O programa jamais deve parar porque uma das 10 entradas apresentou problema.

Considere pelo menos:

### Entrada inválida

Exemplo conceitual:

```text
ABC123
```

### Entrada válida, mas não encontrada

Quando a própria API indicar que o registro não existe.

### Falha de comunicação

Exemplos:

* timeout;
* erro de conexão;
* API indisponível;
* resposta HTTP inesperada.

O erro deve ser registrado e o processamento deve continuar.

Fluxo esperado:

```text
Entrada 1 → sucesso
Entrada 2 → sucesso
Entrada 3 → erro → continua
Entrada 4 → sucesso
...
Entrada 10 → sucesso ou erro
```
